# 나비효과플랜 카페 키워드 원고 작업 프로그램 — 기획서

> 상태: **기획/목업 단계** (구현 착수 전, 검토용 문서) 개정: v0.4 — 2026-09-15 (입력 항목 정리, 모바일 글 모양, 직접 수정·자동 저장, 댓글 사진 표시, Docs 탭 분리, 업로드 계정 구조)

---

## 1. 무엇을 만드는가

키워드 하나를 넣으면 **네이버 카페에 바로 올릴 수 있는 원고 1세트**가 나오는 작업 도구입니다. 원고 1세트 = `[제목]` + `[본문]` + `[댓글 세트]`.

### 핵심 원칙

| 원칙 | 의미 |
| --- | --- |
| 원고는 **제목 + 본문 + 댓글 세트**가 한 덩어리 | 따로 만들지 않고 같이 생성·같이 버전 관리 |
| 다시 만들기가 아니라 **고쳐 만들기** | 댓글 3번만 바꾸고 싶을 때 나머지는 그대로 유지 |
| **직접 고치는 게 제일 빠를 때도 있다** | 글을 더블클릭해 바로 수정, 자동 저장 |
| 댓글1·댓글2는 **대화** | 댓글1 → 글쓴이 → 댓글1 식의 티키타카 |
| 좋은 댓글 세트는 **자산** | 본문을 못 쓰는 원고라도 댓글 세트는 그대로 재사용 |
| 결과물은 **전달 가능한 형태** | 복사 / `.txt` / Google Docs |

## 2. 화면 구성

전체 5개 탭. PC는 좌측 사이드 탭, 모바일은 하단 탭바로 같은 화면을 씁니다.

### 2-1. 원고 생성

| 입력 항목    | 필수 | 설명                                                                       |
| ------------ | ---- | -------------------------------------------------------------------------- |
| 핵심 키워드  | ✅   | 예: `브라질리언 왁싱 모낭염`                                               |
| 브랜드명     |      | 예: `메드젯`                                                               |
| 제품명       |      | 예: `코디세핀 재생크림`                                                    |
| 요청사항     |      | 이번 원고에 대한 자유 지시                                                 |
| 글 성격      |      | **후기형 / 질문형** 둘 중 하나                                             |
| 본문 분량    |      | 짧게(700~~1,000자) / 보통(1,100~~1,500자) / 길게(1,600~2,200자)            |
| 댓글 개수    |      | **1~8개** (기본 4개)                                                       |
| **글 모양**  |      | ☑ 모바일 최적화 (세로로 길게) — **항상 체크된 상태가 기본**                |
| 댓글 세트    |      | `새로 생성` 또는 `기존 댓글세트 가져오기` → 키워드로 원고를 찾아 그 세트만 |
| 쓰지 말 표현 |      | 금칙어                                                                     |

> **뺀 항목** — 업체/브랜드명(브랜드명·제품명으로 대체), 지역, 타깃 독자, 카페 성격, 톤앤매너 4종. 실제로는 같은 브랜드·제품으로 여러 카페에 뿌리는 구조라 지역·카페 성격이 원고를 가르지 않았습니다.

#### 2-1-1. AI 모델 고르기

제미나이 · 클로드 · 챗지피티 API를 모두 연결해 두고 **원고마다 골라서** 씁니다.

카페 원고는 긴 추론이 필요 없고 **자연스러운 한국어를 많이 뽑는** 작업이라, 최고급 모델은 비용만 커지고 결과 차이는 작습니다. 그래서 **저가형끼리 비교해서 고르는 게 맞습니다.**

##### 2단 생성 구조 (선택, 기본 꺼짐)

```
키워드 입력
   ↓
① 기본 생성 — GPT-5.6 Luna           ← 전체
   ↓
② 품질 검사 (자동)
   · 문체가 반복되는가
   · 키워드가 빠졌는가
   · 요청사항을 안 지켰는가
   ↓ 걸린 것만 (대략 10%)
③ 다시 쓰기 — GPT-5.6 Terra (고정)
```

- **기본값은 꺼짐**입니다. 필요할 때만 `이상하면 좋은 모델로 다시 쓰기` 스위치를 켭니다
- 다시 쓰는 모델은 **GPT-5.6 Terra로 고정**합니다 (고르는 칸 없음)

| 상태                                     | 1,000건 비용   |
| ---------------------------------------- | -------------- |
| 꺼짐 (Luna만)                            | 약 **2,940원** |
| 켜짐 (Luna 1,000건 + Terra 재생성 100건) | 약 **5,880원** |

재생성은 먼저 Luna로 전부 쓴 뒤 걸린 것만 다시 쓰는 구조라, **Luna 1,000건 값은 그대로 들고 Terra 100건 값이 더해집니다.** 전부 Terra로 돌리면 29,400원이니 켜도 1/5 값입니다.

##### 설정

- API 키는 회사별로 한 번씩 넣어 둡니다 (OpenAI / Google / Anthropic)
- 기본값은 **GPT-5.6 Luna**, 재생성은 **꺼짐** (켜면 GPT-5.6 Terra)
- 가격이 바뀌면 이 표만 고치면 화면 계산이 따라옵니다

> 가격 출처는 대표님이 확인해 주신 2026-09-15 기준 공식 가격표입니다. 이 중 Anthropic 단가(Haiku 4.5 $1/$5, Sonnet 5 $2/$10, Sonnet 4.6 $3/$15)는 제가 가진 공식 가격표와 일치하는 것을 확인했고, OpenAI·Google 단가는 작업 환경에서 해당 사이트 접속이 막혀 있어 주신 값을 그대로 반영했습니다.

#### 모바일 최적화 (세로로 길게)가 하는 일

체크된 상태(기본)에서는 이렇게 씁니다.

- 한 문단을 **2~3줄**로 끊고 문단마다 빈 줄
- 한 문장이 길어지면 문장 안에서도 줄바꿈
- 결과적으로 모바일 화면에서 **세로로 길게** 읽히는 모양

체크를 풀면 문단을 길게 묶어 PC에서 읽기 좋은 모양으로 씁니다.

### 2-2. 원고 보관함

`키워드.txt` 파일들을 폴더째 올리면 파일명이 곧 키워드가 됩니다. 자세한 건 4장.

### 2-3. 결과 · 버전

**상단 작업 바** — `키워드`와 `요청사항`을 여기서 바로 고치고 `이 조건으로 전체 다시 생성`.

**카드 구성**

| 카드          | 고치는 방법                                                                      |
| ------------- | -------------------------------------------------------------------------------- |
| 제목          | 수정 지시칸 / **더블클릭 직접 수정**                                             |
| 본문          | 수정 지시칸 / **더블클릭 직접 수정**                                             |
| 댓글1 ~ 댓글n | 수정 지시칸 / 더블클릭 직접 수정 / 티키타카 턴 수(1~7) / ☐ 댓글 사진 여기에 첨부 |

**직접 수정과 저장** — 질문 주신 부분입니다.

- 글을 **더블클릭**하면 그 자리에서 편집창으로 바뀝니다 (댓글은 한 줄 단위로도 가능)
- **저장 버튼은 없습니다.** 타이핑을 멈추면 0.8초 뒤 자동 저장, 편집창을 벗어나면 즉시 저장
- 상단에 `자동 저장됨 · 14:32` 로 마지막 저장 시각 표시
- `Esc` 취소 · `Ctrl(⌘)+Enter` 저장 후 닫기
- 직접 고친 카드에는 **`직접 수정함`** 표시가 붙고, **다음 버전을 만들어도 그대로 유지**됩니다 (AI가 덮어쓰지 않습니다. 다시 쓰게 하려면 그 카드에 수정 지시를 적으면 됩니다)
- 되돌리고 싶으면 버전 탭에서 이전 버전으로 이동

**댓글 사진 표시** — 댓글 카드의 `☐ 댓글 사진 여기에 첨부` 를 체크하면, 그 댓글 아래에 `(댓글 사진 여기에 첨부해주세요)` 줄이 생깁니다. 복사·내보내기에도 그대로 따라갑니다. 업로드하는 사람이 어디에 사진을 넣어야 하는지 바로 보라고 두는 표시입니다.

**댓글 세트 바** — `기존 세트 가져오기` 버튼. 가져온 세트는 잠금 상태가 되어 재생성해도 유지.

### 2-4. 내보내기

원고를 **여러 번 만들면 계속 쌓입니다.** 그래서 내보내기 화면은 "지금 원고 1편"이 아니라 **만든 원고 목록에서 골라 한 번에 넘기는** 흐름으로 만듭니다.

```
어떤 원고를 내보낼까요?

만든 원고                         3개 골랐어요
 ☑ 브라질리언 왁싱 모낭염  댓글 4개        방금
 ☑ 팔꿈치 각질            댓글 4개    오늘 14:02
 ☑ 티티베연고             댓글 3개    오늘 13:40
 ☐ 피부 발진 가려움        댓글 4개    오늘 11:20
 ☐ 어루러기 연고 추천      댓글 4개        어제
        [전체 고르기]  [전체 해제]

내보내는 방법   [구글 문서] [txt 파일] [복사하기]

 문서 제목  (비우면 2026-09-15 브라질리언 왁싱 모낭염 외 2건)
 탭 미리보기  [브라질리언 왁싱 모낭염][팔꿈치 각질][티티베연고]
 → 문서 하나에 탭 3개로 들어가요. 탭 이름은 키워드예요.

                            [ 구글 문서로 내보내기 ]
```

| 방법          | 동작                                                                    |
| ------------- | ----------------------------------------------------------------------- |
| **구글 문서** | 문서 1개를 만들고 **고른 원고마다 탭을 추가**해 탭 이름을 키워드로 지정 |
| **txt 파일**  | `키워드.txt` 로 고른 개수만큼 저장. 파일은 **항상 txt**                 |
| **복사하기**  | 지금 보고 있는 원고를 전체 / 본문만 / 댓글만 (사진 자리 표시 포함)      |

- 문서 제목을 비우면 `2026-09-15 브라질리언 왁싱 모낭염 외 2건` 으로 자동 생성
- 원고가 1개든 10개든 같은 화면에서 처리합니다

### 2-5. 설정

메뉴 맨 아래(모바일은 오른쪽 위 톱니 버튼)에 둡니다. 평소에는 안 봐도 되는 것들만 모읍니다.

| 블록 | 내용 |
| --- | --- |
| **API 키** | OpenAI · Google · Anthropic 각각 한 번씩 등록. 등록하면 `등록됨`과 뒷자리만 표시하고, 지우면 그 회사 모델이 선택 목록에서 빠집니다 |
| 기본 모델 | 기본 생성 모델과 다시 쓰기 스위치 상태를 확인. 바꾸는 건 생성 화면에서 |
| 연결된 계정 | 구글 계정(문서 내보내기) · 네이버 계정(업로드) · 카페 열람용 계정 상태를 한눈에 보고 각 화면으로 이동 |
| 저장 | 원고와 보관함은 이 브라우저에 저장됩니다. 백업 파일 내려받기 / 불러오기 |

- 키는 암호화해서 보관하고 화면에는 뒷자리만 보여줍니다
- 키가 없는 회사의 모델은 생성 화면 목록에서 아예 빠지므로, 실수로 고를 일이 없습니다

## 3. 원고 데이터 구조

```
[제목]
브라질리언 왁싱하고 모낭염 올라와서 2주 고생한 후기

[본문]
브라질리언 왁싱 받고 3일쯤 지났을 때였어요.

거기 주변에 좁쌀 같은 게 오돌토돌 올라오더라고요.
…

[댓글1] 티키타카 3턴
댓글1: 저도 왁싱하고 딱 저랬는데 그냥 두면 가라앉나요?
└글쓴이: 저는 안 건드리고 통풍만 신경 썼더니 며칠 지나서 잦아들었어요.
└댓글1: 감사합니다 ㅠㅠ 일단 며칠 더 지켜볼게요

[댓글2] 티키타카 5턴 / 사진첨부
댓글2: 재생크림 뭐 쓰셨는지 여쭤봐도 될까요?
└글쓴이: 저는 코디세핀 들어간 걸로 썼어요.
└댓글2: 향은 어때요? 향 세면 못 쓰거든요
└글쓴이: 향은 거의 없어요.
└댓글2: 감사합니다! 저도 한번 찾아볼게요
(댓글 사진 여기에 첨부해주세요)

[댓글3]
댓글3: 왁싱하고 바로 운동 가는 게 제일 안 좋다고 하더라고요.
```

- **화자 이름(페르소나)은 쓰지 않습니다.** 태그는 `댓글n` 과 `글쓴이` 둘뿐
- 댓글 번호는 **한 줄도 빠짐없이** 붙습니다 (`댓글2` 의 세 번째 말도 `└댓글2:`)
- **티키타카는 기본적으로 댓글1·댓글2만.** 댓글3부터는 단일 댓글이 기본값 (필요하면 카드에서 턴 수를 올리면 됩니다)
- 티키타카 턴 수 = 말풍선 개수. `댓글1 → 글쓴이 → 댓글1` = **3턴**, `댓글2 → 글쓴이 → 댓글2 → 글쓴이 → 댓글2` = **5턴**

내부 저장 형태:

```jsonc
{
  "id": "doc_xxx",
  "keyword": "브라질리언 왁싱 모낭염",
  "brand": "메드젯",
  "product": "코디세핀 재생크림",
  "request": "왁싱 후 3일째 상황부터 시작 / 긁지 말라는 당부",
  "options": { "tone": "review", "length": "medium", "commentCount": 4, "mobileShape": true },
  "versions": [
    {
      "no": 1,
      "title": "...",
      "body": "...",
      "handEdited": ["title"], // 직접 고친 부분 — 재생성해도 유지
      "comments": [
        {
          "index": 1,
          "locked": false, // 가져온 세트면 true
          "photo": false, // 댓글 사진 표시 여부
          "thread": [
            { "by": "commenter", "text": "..." },
            { "by": "author", "text": "..." },
            { "by": "commenter", "text": "..." },
          ],
        },
      ],
    },
  ],
}
```

## 4. 원고 보관함 — 파일 읽는 규칙

### 파일명

`키워드.txt` 형태입니다. **확장자만 떼면 그대로 키워드**가 됩니다. (`브라질리언 왁싱 모낭염.txt` → `브라질리언 왁싱 모낭염`)

꼬리말이 붙은 파일(`_최종`, `v2`, `(1)`, 날짜)도 보조 규칙으로 정리하지만, 지금 규칙이라면 거의 손댈 일이 없습니다. 추출 결과는 카드에서 직접 고칠 수 있습니다.

### 파일 안 내용

`제목:` 같은 표기가 없는 형식이므로 이렇게 읽습니다.

| 부분        | 규칙                                                          |
| ----------- | ------------------------------------------------------------- |
| 제목        | **첫 줄** (`제목:` 표기가 있으면 그것을 우선)                 |
| 본문        | 첫 빈 줄 다음부터, 댓글 시작 전까지                           |
| 댓글 세트   | `댓글1` `댓글 1` `1.` 같은 **번호 표기가 처음 나오는 줄**부터 |
| 글쓴이 답글 | `ㄴ` `└` `->` 로 시작하는 줄                                  |

경계를 못 찾은 파일은 버리지 않고 **`확인 필요`** 목록으로 모읍니다. 거기서 키워드를 적고 댓글 시작 지점을 직접 찍어주면 보관함에 들어갑니다.

> 전달은 **구글 문서**가 편하다고 하셨으니, `.txt` 와 함께 **`.docx` / 구글 문서 링크**도 같은 규칙으로 읽도록 만듭니다.

### 올리는 방법 세 가지

보관함 화면 **맨 위**에 올리기 영역을 둡니다.

| 방법 | 설명 |
| --- | --- |
| 폴더 올리기 | 폴더를 끌어다 놓으면 하위 폴더까지 한 번에 (`.txt`, `.docx`) |
| **구글 문서 주소 넣기** | 폴더 선택으로는 구글 문서를 못 고르므로, **주소를 붙여넣는 칸**을 따로 둡니다. 구글 드라이브 **폴더 주소**를 넣으면 안에 있는 문서를 한 번에 읽습니다 |
| 카페 글 가져오기 | 아래 5-1 방식 |

### 키워드 카드 · 검색 · 정렬

- 카드 한 장 = 원고 하나. 큰 글씨가 **키워드**, 아래에 제목·댓글 요약·날짜·브랜드/제품·파일명
- **검색** — 키워드 · 제목 · 브랜드를 한 칸에서. 입력하는 즉시 걸러짐
- **정렬** — `최근 올린 순` / `키워드 가나다순` / `댓글 많은 순` / `최근 쓴 순`
- 카드 버튼 — `댓글세트 쓰기` · `원고 보기` · `어투 학습` 체크

### 보관함이 쓰이는 두 곳

1. **어투 학습** — 체크한 원고의 문체를 생성에 반영 (참고 원고를 프롬프트에 함께 전달)
2. **댓글 세트 재사용** — 생성 화면 · 보관함 카드 · 결과 화면 세 곳에서 같은 검색 패널로

## 5. 네이버 카페 — 열람과 업로드

읽어오는 것과 올리는 것은 화면이 다릅니다. **읽어오기는 보관함**, **올리기는 업로드 화면**입니다.

### 5-1. 카페 글 읽어오기 (보관함 기능)

읽을 수 있는 **계정 하나**만 있으면 해결됩니다. 수집은 3단으로 자동 폴백합니다.

| 순서 | 방법                                                       | 되는 범위                |
| ---- | ---------------------------------------------------------- | ------------------------ |
| 1    | URL 붙여넣기 → 서버가 공개 조회 API로 수집                 | 전체 공개 글             |
| 2    | **열람용 계정 등록** 또는 카페 글에서 누르는 **수집 버튼** | 멤버 공개 · 등급 제한 글 |
| 3    | 직접 붙여넣기                                              | 항상                     |

수집 항목은 제목 · 본문 · 댓글(작성순) · 대댓글 관계이며, 대댓글 관계를 보존하므로 **수집한 글의 댓글 세트도 재사용 대상**이 됩니다.

### 5-2. 업로드 화면 구성

업로드 화면은 위에서부터 이렇게 쌓습니다.

| 순서 | 블록 | 내용 |
| --- | --- | --- |
| 1 | **올릴 원고 고르기** | 만든 원고 목록에서 이번에 올릴 글을 고름 |
| 2 | **올릴 곳** | 카페 주소를 넣고 게시판을 불러와 고름 (아래 5-3) |
| 3 | **계정 연결 방식** | 아래 3가지 중 선택 |
| 4 | **계정 관리** | 별칭 · 아이디 · 비밀번호를 넣어 저장. 등록한 계정이 5번에서 선택지로 뜸 |
| 5 | **계정 배정** | 본문 · 글쓴이 답글 / 댓글1 / 댓글2 … 역할마다 계정 지정 |
| 6 | **올리는 간격** | 아래 5-4 |

> **열람용 계정은 업로드 화면에서 뺐습니다.** 지적하신 대로 그건 _카페 글을 읽어오는_ 기능이라, 보관함의 `카페 글 가져오기` 안으로 옮겼습니다.

#### 계정 연결 방식

| 방식 | 동작 | 계정 여러 개일 때 |
| --- | --- | --- |
| **A. 서버에 계정 저장** | 계정을 한 번 등록해 두면 예약과 순차 등록이 자동으로 돌아감 | ⭕ 편함 |
| **B. 크롬에 로그인해 두고 올리기** | 내 브라우저에서 등록. 서버가 계정을 모름 | △ 댓글 계정마다 바꿔 로그인 |
| **C. 올릴 때마다 직접 로그인** | 저장하지 않고 그때그때 입력 | △ 원고 많으면 번거로움 |

계정을 저장할 때는 **비밀번호를 암호화해서 보관하고, 로그인한 뒤에는 세션만 들고 있습니다.** 계정을 지우면 저장된 정보도 같이 지웁니다.

### 5-3. 올릴 카페와 게시판 고르기

업로드에서 가장 먼저 정해야 하는 값입니다.

```
카페 주소  [ https://cafe.naver.com/starkart ]  [게시판 불러오기]
최근 올린 카페  (리그오브레전드) (서울맘스러브) (시크먼트) (다낭 아지트)
        ↓
✓ 서울맘스러브
  cafe.naver.com/starkart · 글쓸 수 있는 게시판 4개

게시판   [ 수다방 ▾ ]
```

| 단계 | 하는 일                                                             |
| ---- | ------------------------------------------------------------------- |
| 1    | 카페 주소를 붙여넣으면 주소에서 카페를 찾습니다                     |
| 2    | 그 카페의 **게시판 목록**을 불러옵니다                              |
| 3    | **내 계정이 글을 쓸 수 있는 게시판만** 남겨서 보여줍니다            |
| 4    | 한 번 쓴 카페는 `최근 올린 카페`로 남아 다음부터는 한 번에 고릅니다 |

- 게시판 목록은 로그인한 계정 기준이라, **계정 등록 뒤에 불러오는 게 정확합니다**
- 등급 제한으로 글을 못 쓰는 게시판은 목록에서 빼거나 잠금 표시를 합니다
- 카페마다 게시판 구조가 달라서, 불러오기가 실패하면 게시판 주소를 직접 넣는 칸을 보조로 둡니다

### 5-4. 올리는 간격

세 가지를 각각 **1분 ~ 5분** 사이에서 지정합니다.

| 항목                         | 기본값 |
| ---------------------------- | ------ |
| 본문 올린 뒤 첫 댓글까지     | 3분    |
| 댓글과 댓글 사이             | 2분    |
| 댓글 달린 뒤 글쓴이 답글까지 | 1분    |

## 6. 디자인 — 토스 디자인 시스템

기능이 많아 복잡해 보이는 문제를 줄이기 위해 **토스 디자인 시스템**을 기준으로 다시 잡았습니다.

### 색

| 용도        | 값                                                 |
| ----------- | -------------------------------------------------- |
| 포인트      | `#3182F6` (누를 때 `#1B64DA`, 연한 배경 `#E8F3FF`) |
| 바탕 · 카드 | `#F2F4F6` 바탕 위에 흰색 카드                      |
| 글자        | `#191F28` → `#4E5968` → `#8B95A1` (3단계)          |
| 경고 · 확인 | `#F59F00` · `#00C471`                              |

다크 모드도 같은 구조로 한 벌 더 정의합니다.

### 타이포

- **Pretendard** 우선, 없으면 Inter + Noto Sans KR
- 화면 제목 24px Bold / 카드 제목 16px Bold / 본문 15px / 설명 13px
- 자간 -0.02em, 제목은 줄바꿈 균형(`text-wrap: balance`)

### 컴포넌트

| 컴포넌트       | 규칙                                                                |
| -------------- | ------------------------------------------------------------------- |
| 카드           | 흰 배경, 라운드 16px, 테두리 없이 아주 옅은 그림자                  |
| 버튼           | 라운드 12px, 높이 44px(주요 버튼 52px), 굵기 600                    |
| 세그먼트       | 후기형·질문형처럼 **2~3개 선택은 가로 세그먼트**로 (세로 나열 금지) |
| 스위치         | 켬/끔은 토글 스위치 (모바일 최적화 등)                              |
| 스테퍼         | 숫자는 `− 4개 +` 스테퍼 (댓글 개수)                                 |
| 칩             | 상태 표시는 작은 알약 모양 칩                                       |
| 하단 고정 버튼 | 각 화면의 주요 동작 1개를 하단에 고정                               |
| 아이콘         | 선 굵기 1.8px, 끝이 둥근 라인 아이콘                                |

### UX 라이팅 — 해요체

| 이전 | 바꾼 문구 |
| --- | --- |
| 원고 생성 | **원고 만들기** |
| 키워드 하나로 원고 한 세트 | **어떤 키워드로 쓸까요?** |
| 다음 버전 생성 | **다음 버전 만들기** |
| 수정 지시를 적은 카드: 0개 | **고칠 곳을 적거나 글을 두 번 눌러 보세요** |
| 자동 저장됨 · 14:32 | **저장됨 14:32** |
| 가져온 세트 · 재생성 안 함 | (칩을 지우고) **가져온 댓글이에요. 다시 만들어도 그대로 있어요** — 섹션에 한 번만 |

- 짧은 문장, 존댓말 해요체, 버튼은 동사로 끝냅니다
- **같은 정보를 두 번 쓰지 않습니다.** 예전 화면에서 `댓글1 / 티키타카 3턴 / 가져온 세트 · 재생성 안 함` 이 카드마다 반복되던 것을, 카드에는 `댓글1`·`티키타카 3턴`만 두고 가져온 세트 안내는 **섹션 위 한 줄**로 옮겼습니다

### 화면 정리

- 왼쪽 메뉴 이름을 짧게: 생성 · 보관함 · 결과 · 내보내기 · 업로드
- 화면마다 카드 2~3개로 제한, 설명 문구는 한 줄까지
- 보관함의 파일 읽는 규칙 표, 카페 수집 3단 설명 같은 **설명용 표는 화면에서 빼고 이 문서에만** 둡니다
- 상단 키워드 칩, 예상 소요 시간 배지처럼 **없어도 되는 요소는 삭제**

> 참고로 주신 핀터레스트 링크(`pin.it`)는 이 작업 환경의 네트워크 정책에서 차단되어 열지 못했습니다. 토스 디자인 시스템 기준으로 먼저 맞춰 두었으니, 무드가 다르면 이미지를 캡처해서 보내 주시면 바로 반영하겠습니다.

## 7. 기술 구성

| --- | --- | --- |

| 문서 내보내기 | Google Docs API (브라우저에서 직접 호출) | 서버가 구글 비밀키를 들고 있지 않아도 됨 |

## 9. 확인이 필요한 사항

1. **업로드 계정 연결 방식** — 5-2의 A / B / C 중 하나. 이것만 정해지면 업로드 단계 설계가 끝납니다.
2. **원고 파일 3~5개** — 본문과 댓글 경계를 어떻게 잡는지 확정하려면 실제 파일이 필요합니다. 현재 규칙(번호 표기 기준)이 안 맞으면 `확인 필요`로 빠지는 파일이 늘어납니다.
3. **댓글 계정 개수** — 보통 한 원고에 계정 몇 개를 쓰시는지 알려주시면 계정 배정 화면을 거기 맞춰 잡습니다.
4. **발행 관리 시트 연동** (선택) — 주신 시트가 `날짜 / 카페명 / 키워드 / 링크 / 순위 / 카페탭·통검 / 브랜드 / 제품 / 조회수` 구조던데, 업로드까지 만들면 **등록 결과를 이 시트에 자동으로 한 줄 추가**할 수 있습니다. 필요하시면 업로드 단계에 같이 넣겠습니다.
